# 人工请求

有些事只有人在板子旁边才能做：把 USB 线插到某个口、接一根串口线、按一下 RESET、按住 BOOT 再复位。agent 做不了这些，也不该猜「应该已经插好了」。人工请求是让它**请人做、等结果**的通道：请求存在 boardd 的数据库里，页面（「人工请求」）上等人点「我做好了」或「做不了」，请求方拿到结果再继续。

请求和板子的锁没有关系：它是「请你做这件事」，不占板子。做完之后的验证（看串口、看下载口、`boardlab list`）仍然由请求方自己做。

## 命令行

```sh
boardlab ask "把 K3 板的 USB 线插到 2-1.1" --kind 插拔 \
  --body "插好后串口会打印 ROM: usb download handler；下载口应该出现在 usb:2-1.1" --timeout 10m
```

| 参数 | 说明 |
|---|---|
| 标题（位置参数） | 一句话说清要人做什么 |
| `--body <说明>` / `--body -` | 怎么做、做完是什么样。`-` 从标准输入读，适合长说明 |
| `--kind <标签>` | 给页面上分类：插拔、接线、按键、测试…… 默认 `task` |
| `--context <JSON>` | 附带给页面和以后查看的 JSON（端口号、板名等） |
| `--key <键>` | 重试键：同一个人、同一个 key 的请求还在等人时，再 ask 不会产生第二条 |
| `--timeout <时长>` | 最多等多久，默认 `10m` |
| `--no-wait` | 只登记，不等待 |

退出码：`0` 表示人点了「我做好了」（输出里有人的说明）；`3` 表示人点了「做不了」（输出里有原因）；超时是错误（退出码非 0），请求仍然在等人，可以 `boardlab ask list` 再看。

```sh
boardlab ask list [--all]                 # 还在等人的（--all 连已完成、已取消的）
boardlab ask done <id> [--note 说明]      # 替人关掉：做好了（人在页面上点也一样）
boardlab ask cancel <id> [--note 说明]    # 替人关掉：做不了
```

## HTTP

| 接口 | 用途 |
|---|---|
| `POST /api/human/ask` | 登记：`title`、`body`、`kind`、`context`、`key`。返回这条请求 |
| `GET /api/human/requests` | 看：`status=open\|done\|canceled\|all`（默认 open）、`limit`（默认 100）。返回 `{open, items}` |
| `GET /api/human/request?id=<id>&wait=<秒>` | 等一条：人做完或被取消后返回；`wait` 0–60 秒（默认 0），到时间还在等人就返回当前状态 |
| `POST /api/human/resolve` | 处理：`id`、`status=done\|canceled\|open`（open 是重新打开）、`note` |

写脚本时用 `?wait=20` 轮询（一次不要超过 30 秒），拿到 `done`/`canceled` 就停。`context` 是 JSON，原样保存。

## 页面

- 顶部导航的「人工请求」页列出还在等人的请求：标题、说明、谁请的、什么时候；每一条有「我做好了」和「做不了」。
- 新请求会用页面通知（浏览器允许时是系统通知）、消息和顶部横幅提醒在页面里的人；点横幅直接到这一页。
- 人点「做不了」时写一句原因（例如「线不够长」），请求方会看到并换办法，而不是一直等。

请求在 boardd 重启和升级后都还在（存在 `boardd` 的 SQLite 里）。页面上的身份（右上角的名字）就是「谁点的」记录，用于追责和区分几个人一起用同一个页面。

## 什么时候用

- 要用；`boardlab ask` 只用于**板子外面**的事。拿锁、复位、串口、启动、刷机都是 `boardlab` 自己能做的命令，不要转给人。
- 说明里写清楚的**可验证现象**（串口出现哪一行、哪个下载口出现、板子上的灯），人照着做，请求方做完后自己验证。
- 人在忙时不要连发；给足 `--timeout`，用 `--key` 让重试不打扰人两次。
