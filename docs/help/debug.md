# 调试一块板子

调试和串口、下载口一样，是板子的一种能力：板子所在的后端说它有哪条调试路（谁能调试它、能做什么），boardlab 照着显示和操作。有的板子没有调试口，页面和命令都会直说；有的板子用两颗 GPIO 位操作出调试链路，有的板子用 USB 调试器——对 boardlab 来说是同一种东西。

## 用什么看

- 板子页（Modern 前端）上有「调试」一块：提供者的名字和说明、它能做什么（暂停、继续、单步、寄存器……）、会话在不在跑、跑到哪里（端点），在跑时下面就是它输出的字节流。
- 命令行：`boardlab debug <板子>` 看这条路；`boardlab debug <板子> halt|run|reset|step|regs` 做一个动作；`boardlab debug stream <板子>` 把输出打到终端（Ctrl-C 停）。
- 动作的名字来自后端：板子报什么，命令和页面就有什么，没有的会明确说「它提供的是……」。

## 会话跟着锁走

启动调试会话要拿板子的锁（没拿锁时命令会提示先 `boardlab lock`）。会话跑在板子所在的主机上，生命周期就是这把锁：`boardlab unlock`（或者锁被别人接手）会让会话一起停掉——下一个人拿到的板子不会带着你的断点。

- 会话在跑时别人不能抢这块板子做复位、启动、刷机（锁在你手上）。
- 想让别人用，先停会话：`boardlab debug stop` 或页面上「停止调试会话」，再放锁。

## 它是怎么来的

调试路由板子所在主机上的**提供者**实现，板子的登记里写着用哪一个（`boardlab show <板子> --json` 的 `lab.debug`；主机上的 `boardctrl status` 列出这台主机装了哪些提供者）。站点可以带自己的提供者，不需要改 boardlab：一个新平台的调试器只要按同一套接口上报「有什么、怎么开会话、怎么做动作」，页面、命令和锁规则都不用动。
